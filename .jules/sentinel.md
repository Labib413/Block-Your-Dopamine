## 2025-05-15 - Mitigation of Reverse Tabnabbing and URL Injection
**Vulnerability:** Widespread use of `window.open(url, '_blank')` and `<a>` tags with `target="_blank"` without `rel="noopener noreferrer"`, combined with unsanitized user-provided URLs (avatars, resource links) being rendered directly.
**Learning:** The application allows users to input URLs for various features (Distraction Guard, Resources, Avatars). Without centralized validation and secure opening mechanisms, these inputs could be used for XSS via `javascript:` protocols or to perform Reverse Tabnabbing attacks where a malicious destination tab takes control of the original application tab.
**Prevention:** Use the centralized `isValidUrl` and `safeOpen` utilities in `src/lib/utils.ts`. `isValidUrl` blocks dangerous protocols and restricts `data:` URIs to safe image types. `safeOpen` ensures that all new windows are opened with `noopener,noreferrer` and have their `opener` set to `null`, while still allowing for custom window features like dimensions.
